# Comparison: TrueID, RadiUID, and Cisco ISE (IP-to-user mapping)

This page compares **TrueID**, **RadiUID**, and **Cisco Identity Services Engine (ISE)** only in the scope of mapping an IP address to a user (identity correlation / passive identity). It is not a comparison of network access control (NAC), 802.1X policy, guest access, TrustSec segmentation, posture, or device administration.

Claims about RadiUID and Cisco ISE are taken from the primary sources listed at the end and were checked on 21 November 2026. Claims about TrueID are taken from this repository's README and documentation. No performance figures, market-share numbers, or prices are given here unless a cited primary source states them.

TrueID is not an eKYC or identity-verification product and is unrelated to [trueid.me](https://trueid.me) or the Vietnamese TrueID company.

## TrueID vs RadiUID

RadiUID is a focused open-source tool: it reads RADIUS accounting and pushes user-to-IP mappings to Palo Alto User-ID. That is the problem it was built to solve, including environments that do not use Active Directory or where endpoints do not authenticate directly to a domain controller. ([RadiUID README](https://github.com/PackeTsar/radiuid/blob/v2.5.0/README.md))

TrueID also ingests RADIUS accounting, but it is a multi-source correlator. In this repository it additionally documents Active Directory syslog, DHCP syslog, VPN syslog, and a Windows agent, plus a dashboard and API for SOC/NOC operators, User-ID push to both PAN-OS and FortiGate, and SIEM forwarding. RadiUID's documented consumer is Palo Alto User-ID only.

RadiUID remains a smaller, single-purpose service (FreeRADIUS + a Python CLI on Linux or Docker). TrueID is a larger engine-plus-web deployment. The two projects use different open-source licenses (MIT vs GPL-3.0), which matters if you plan to modify or distribute the code; read each license for the actual terms.

This page does not claim compatibility of RadiUID with PAN-OS versions outside the 6.X–8.X range documented in its README, and it does not claim incompatibility either.

## TrueID vs Cisco ISE

Cisco ISE is a commercial NAC and AAA platform. Mapping users to IP addresses is one of its functions, not its whole purpose. In ISE, that function appears as **passive identity** (collecting identities from providers and publishing them) and as **Easy Connect** (using a PassiveID/WMI-learned Active Directory login, together with MAB and RADIUS accounting, to authorize a session and optionally attach a Security Group Tag). Full ISE can also learn identity as part of active 802.1X or other AAA, which is outside the mapping-only scope of this page.

Compared with ISE in this narrow scope:

- TrueID is open-source (MIT) and is operated by the user. ISE is licensed per concurrent active endpoints, in tiers.
- TrueID's documented sources are RADIUS accounting, AD/DHCP/VPN syslog, and a Windows agent. ISE's documented passive providers are broader in some directions (WMI and agents against Active Directory, SPAN of Kerberos, a programmatic REST API, and many syslog templates) and sit inside a Cisco policy platform.
- TrueID's documented consumers are its own API and dashboard, PAN-OS and FortiGate User-ID, and SIEM. ISE's documented mapping consumers are pxGrid subscribers (with session context) and, for Easy Connect, ISE authorization / CoA and optional SXP. Publishing session context to pxGrid clients requires an Advantage (or Premier) license; Easy Connect itself is available from the Essentials tier.
- TrueID does not replace ISE as a NAC or AAA server. This page does not claim feature parity with ISE beyond the sources and outputs listed above.

The standalone ISE-PIC product covered the passive-identity slice of ISE (collect, map, and share identities over pxGrid) without ISE's authentication and authorization services. It is no longer sold (end-of-sale 3 November 2025). ([ISE-PIC end-of-sale bulletin](https://www.cisco.com/c/en/us/products/collateral/security/ise-passive-identity-connector/ise-pic-eol.html))

## Where each is a better fit

These notes follow from the sourced differences above. They are not rankings.

- **RadiUID** is a better fit when the requirement is only RADIUS accounting into Palo Alto User-ID, and a small Linux or Docker service with a CLI is enough.
- **Cisco ISE** is a better fit when IP-to-user mapping is needed as part of a Cisco ISE deployment — for example to feed pxGrid subscribers, or to use Easy Connect for Active Directory users whose endpoints may not run 802.1X — or when the organization already standardizes on ISE for access policy.
- **TrueID** is a better fit when operators want an open-source correlator that ingests several telemetry sources, exposes a dashboard and API for SOC/NOC use, and can push User-ID to PAN-OS and FortiGate and forward events to a SIEM, without deploying ISE.
